proposed-text: |
  On a Mac where Medusa owns ~/.claude and Flux lives in ~/.claude-flux, a
  Claude desktop app session opened on the Flux checkout runs under
  ~/.claude, so Medusa's hooks fire on Flux, not Flux's. Medusa's
  auto-commit-push Stop hook does not know Flux is a shared checkout: it
  saw uncommitted edits on main, created an auto/wip-<timestamp> branch,
  committed the edits there with an "auto:" message and pushed that
  branch. The session had to move the commit back to main and delete the
  branch. The desktop app has no way to start a session with
  CLAUDE_CONFIG_DIR=~/.claude-flux, so Flux work on such a machine needs
  the CLI, or Flux's README should warn that a desktop session there runs
  under the other config repo. Committing before the turn ends avoids the
  sweep, but that only hides the mismatch.
